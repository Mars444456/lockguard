## Возможности

Сайт, учебный пример и серверный кабинет поддерживают **RU / EN**. Переключатель сохраняет язык в браузере; прямые ссылки: [русский](https://mars444456.github.io/lockguard/?lang=ru) и [English](https://mars444456.github.io/lockguard/?lang=en). Переключение не меняет SQL, названия объектов и пользовательские данные.

- Разбор синтаксиса PostgreSQL через `libpg-query` 18.1.5 (WASM).
- 12 правил для индексов, внешних ключей, изменений типов, `NOT NULL`, таймаутов и других операций.
- CLI: проверка файлов и каталогов, изменённых файлов и содержимого индекса Git перед коммитом.
- Отчёты в терминале, JSON, Markdown и SARIF.
- Черновики многофазных миграций и ограниченное автоисправление `CREATE INDEX` и таймаутов.
- Локальный HTTP dashboard, браузерная демонстрация и код Telegram-бота.
- Подтверждение владения email одноразовой ссылкой перед созданием и принятием приглашений; почтовая доставка подключается оператором.
- Регистрация, вход и личный кабинет: отдельные ключи API, история и настройки для каждой организации.
- Бесплатный проект в браузере: явное сохранение до 20 проверок на устройстве, экспорт/импорт JSON и повторный анализ открытого SQL без аккаунта и сервера. История и файлы не зашифрованы; храните конфиденциальный SQL приватно. Очистка данных сайта удаляет локальную историю. История браузера хранится отдельно от истории серверного кабинета.
- SQLite с транзакциями, переносом старого JSON и проверяемыми резервными копиями.
- Импорт структуры SQL/JSON для анализа существующих индексов и подтверждённых ограничений.
- Pro в серверном кабинете: до 10 схем, 1000 проверок, сравнение замечаний и командное ревью с ролями и историей решений.
- GitHub webhook с проверкой подписи и анализом SQL из PR; публикация commit status включается отдельно.
- Серверная интеграция Robokassa с тестовым режимом, проверкой ResultURL и защитой от повторной обработки платежа.

**Проверка не гарантирует отсутствие простоев.** Парсер проверяет синтаксис, а правила покрывают часть операций PostgreSQL. Неподдерживаемые конструкции получают `LG-000` и `analysisComplete: false`, требуя ручной проверки. Числовые прогнозы длительности, нагрузки и потерь удалены: SQL не исполняется. Подробности и незакрытые условия платного запуска: [состояние продукта](PRODUCT-STATUS.md).

## Быстрый запуск

Требуется **Node.js 24 или новее** с npm. Локальная проверка выполнена на Node.js 24.12.0, CI использует Node.js 24. Сервер применяет встроенный модуль `node:sqlite`; в Node.js 24.12 он выводит предупреждение ExperimentalWarning.

```sh
git clone https://github.com/Mars444456/lockguard.git
cd lockguard
npm ci --ignore-scripts
node bin/lockguard.js check fixtures/10_safe_migration.sql
node bin/lockguard.js rules
npm test
```

## Локальный CLI

Проверка собственных миграций:

```sh
node bin/lockguard.js check ./migrations
node bin/lockguard.js check ./migrations --strict --format=json
node bin/lockguard.js check ./migrations --format=sarif --output=lockguard.sarif
node bin/lockguard.js check --changed origin/main
node bin/lockguard.js check --staged
```

Коды завершения: **0** — нет нарушений выбранного порога; **1** — найдены нарушения; **2** — ошибка запуска, чтения или анализа. `--strict` также блокирует предупреждения. Не считайте любой ненулевой код успешной работой анализатора.

`--staged` читает SQL из индекса Git, включая частично добавленные файлы. Этот режим нельзя совмещать с `--fix`: исправьте рабочие файлы, проверьте diff и добавьте их заново.

## Каталог правил

| Правило | Что проверяет |
|---|---|
| LG-001 | Добавление колонки с volatile или нетривиальным DEFAULT |
| LG-002 | Построение индекса без CONCURRENTLY |
| LG-003 | Добавление внешнего ключа без NOT VALID |
| LG-004 | Смена типа колонки с риском перезаписи таблицы |
| LG-005 | Прямое добавление UNIQUE без конкурентного построения индекса |
| LG-006 | Немедленное удаление колонки или таблицы |
| LG-007 | Ограничения VACUUM, блокировки VACUUM FULL и проверка настроек autovacuum |
| LG-008 | Отсутствующий или неэффективный lock_timeout перед DDL |
| LG-009 | SET NOT NULL без предварительно проверенного ограничения |
| LG-010 | CONCURRENTLY внутри транзакционного блока |
| LG-011 | Внешний ключ без подтверждённого индекса на дочерних колонках |
| LG-012 | TRUNCATE; REFRESH MATERIALIZED VIEW без CONCURRENTLY |

Отдельное нарушение `LG-000` означает неполный анализ и необходимость ручной проверки. Исходный код проверок находится в [src/core/rules](src/core/rules/), полный вывод доступен через `node bin/lockguard.js rules`.

## GitHub Action

Добавьте в свой репозиторий `.github/workflows/lockguard.yml`:

```yaml
name: PostgreSQL migration audit
on:
  pull_request:
    paths:
      - 'migrations/**'
      - '.github/workflows/lockguard.yml'

permissions:
  contents: read

jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 24
      - uses: Mars444456/lockguard@main
        with:
          migrations_dir: ./migrations
          severity: HIGH
          format: github-pr-comment
          output_file: lockguard-report.md
      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: lockguard-report
          path: lockguard-report.md
          if-no-files-found: ignore
```

Action проверяет указанный каталог и сохраняет отчёт; комментарий в PR сам по себе не публикуется. Для воспроизводимости можно закрепить проверенный SHA коммита вместо `main`.

CI этого проекта запускает тесты, проверяет соответствие браузерной сборки исходникам и анализирует SQL, изменённый в PR относительно его базового коммита. Учебные SQL в `fixtures/` и `test/` проверяются тестами и исключены из аудита реальных миграций.

Перед публикацией выполните `npm run check:privacy`. Эта проверка также включена в CI и сборку сайта: она останавливает их при обнаружении ссылок на разговоры ChatGPT, приватных ключей и случайно добавленных в Git файлов окружения, баз или каталогов `private/`, `data/`, `backups/`. Проверяются рабочие файлы и их копии в индексе Git; в сообщении об ошибке выводятся только путь, строка и тип проблемы. Сам `git push` эта команда автоматически не перехватывает: CI запускается уже после отправки коммита. Проверка не заменяет просмотр публикуемых материалов и не распознаёт личные данные на изображениях или в произвольном тексте.

## Пример риска и черновики исправлений

```sql
CREATE INDEX idx_orders_user_id ON orders(user_id);
```

На существующей таблице правило `LG-002` предупреждает о блокировке записи при обычном построении индекса. Вариант для ручной проверки:

```sql
SET lock_timeout = '3s';
CREATE INDEX CONCURRENTLY idx_orders_user_id ON orders(user_id);
RESET lock_timeout;
```

`CREATE INDEX CONCURRENTLY` нельзя запускать внутри транзакционного блока; применимость также зависит от таблицы, схемы и вашего migration runner.

```sh
node bin/lockguard.js split ./migrations/001.sql --write --out-dir=./migration-drafts
node bin/lockguard.js check ./migrations/001.sql --fix
```

Результаты `split` — **черновики для проверки**, не готовая замена исходной миграции. Сверьте все исходные операции, перенос данных, ограничения, порядок релизов и откат. Шаблоны backfill требуют ограничения размера пакетов и проверки на тестовой базе. `--fix` меняет исходный файл, поэтому перед запуском сохраните его в Git и просмотрите diff после изменения.

## Локальный dashboard и API

```sh
npm start
```

Откройте [http://localhost:3000](http://localhost:3000). Не открывайте `src/ui/index.html` через `file://`: интерфейсу нужен сервер API.

Для новой установки скопируйте `.env.example` в `.env`; существующий `.env` сохраните. Откройте **Войти / Регистрация**, создайте аккаунт с email, паролем от 12 символов и названием организации. Пользователь управляет ключами и историей своей организации без администраторского токена.

`LOCKGUARD_ADMIN_TOKEN` — отдельный секрет оператора для основного профиля и текущих настроек оплаты. Кнопка «Администратор» сохраняет его только в памяти вкладки. Не передавайте его клиентам. Без входа приватные API возвращают 401.

Исходный SQL для анализа передаётся серверу локального dashboard. Статическая демонстрация на GitHub Pages выполняет анализ в браузере. **GitHub Pages не запускает Node.js API и не принимает платёжные уведомления.**

Данные хранятся в `data/lockguard.sqlite3`. Каждому аккаунту принадлежит отдельная организация; её идентификатор определяется по серверному сеансу, а не по полю в запросе. Ключи API также привязаны к организации. Смена пароля отзывает предыдущие сеансы, выход очищает приватные данные в интерфейсе.

Если обнаружен прежний `data/lockguard.db.json`, данные импортируются один раз; исходный JSON и отдельная копия `.pre-sqlite-*.bak` сохраняются для восстановления. Если `LOCKGUARD_DB_FILE` указывает на `.json`, SQLite создаётся рядом с расширением `.sqlite3`. Перед переходом остановите старую версию сервера, чтобы она не продолжала записывать JSON. Старые данные остаются в основном профиле оператора и не присваиваются первому зарегистрировавшемуся клиенту.

SQLite поддерживает несколько процессов на одном сервере. Для нескольких хостов нужна отдельная серверная БД. В Pro доступны приглашения в организацию и роли владельца, редактора и рецензента. Резервный код восстанавливает доступ без почтового сервиса; доставка писем восстановления требует настройки отправителя. Подтверждение email при регистрации пока не реализовано. Сервер проверяет права и Pro при каждом запросе. [Ревью, восстановление и размещение](OPERATIONS.md).

Снимки SQL импортируются в формат v2 с исходными типами столбцов; JSON v1 продолжает приниматься без сведений о типах. LG-004 различает подтверждённый риск переписи, известное расширение VARCHAR и недостаток контекста. Отсутствие переписи не отменяет ACCESS EXCLUSIVE. Автоматическая замена столбцов при смене типа не генерируется без проверки зависимостей. Backfill для нового столбца выполняется ограниченными пакетами по 5000 строк с отдельной проверкой завершения.

Схемы загружаются во вкладке **«Схемы PRO»** в формате SQL или JSON до 512 КБ. SQL не выполняется; сохраняется только нормализованная структура. Поддерживается ограниченный набор `CREATE TABLE`, `CREATE INDEX` и определений ограничений, а не произвольный `pg_dump`. Готовый пример JSON: [schema.snapshot.json](examples/schema.snapshot.json).

В открытом CLI:

```sh
node bin/lockguard.js check ./migration.sql --schema=./examples/schema.snapshot.json --strict
```

Для нескольких файлов нужен `--isolated`: каждый проверяется независимо от остальных по одному снимку. Снимок не воспроизводит последовательность нескольких миграций и не сверяется с живой базой. Обновляйте его после изменений структуры. Частичные, невалидные индексы и индексы с неподтверждённой семантикой не считаются доказательством покрытия FK. Проверенные `CHECK ... IS NOT NULL` учитываются для PostgreSQL 12+.

Pro активируется на сервере. Пока магазин подключается, оператор может выдать доступ существующему аккаунту локальной командой из каталога проекта:

```sh
npm run pro -- grant user@example.com 30
npm run pro -- revoke user@example.com
```

Замените email адресом зарегистрированного аккаунта. Команды доступны владельцу файлов сервера, не создают платёж и не публикуют API для самостоятельного повышения тарифа. Срок проверяется на сервере; покупка разового аудита не включает Pro. После окончания Pro экспорт и удаление собственных схем доступны, анализ с ними и сравнение блокируются. При новой записи история сокращается до лимита Community. Поля старых месячных квот пока информационные: новый лимит количества анализов не вводился.

Для API передавайте `schemaId` из `/api/v1/schemas` вместе с `sql` и ключом своей Pro-организации в `/api/v1/analyze`. Старые отчёты без структурированных замечаний и неполный анализ не участвуют в сравнении.

## Резервные копии

HTTP-сервер создаёт проверенную копию при запуске, если копия отсутствует или устарела, затем каждые 24 часа. По умолчанию сохраняются 7 последних копий в `data/backups/`. Настройки: `LOCKGUARD_BACKUP_DIR`, `LOCKGUARD_BACKUP_HOURS`, `LOCKGUARD_BACKUP_RETENTION`.

```sh
npm run backup
npm run restore -- data/backups/FILE.sqlite3 data/restored.sqlite3
```

Замените `FILE.sqlite3` настоящим именем копии. Восстановление создаёт **новый файл**, проверяет целостность и отзывает браузерные сеансы. Существующая БД не перезаписывается. Для переключения остановите сервер, задайте `LOCKGUARD_DB_FILE=data/restored.sqlite3` и запустите его снова.

Копии содержат приватные данные и хеши паролей. Держите каталог закрытым. Копия на том же диске не защищает от его отказа: настройте отдельный защищённый диск или собственное внешнее хранилище. Автоматическая отправка копий во внешние сервисы не настроена. Подробнее — [аккаунты, хранение и восстановление](DEPLOYMENT.md#хранение-и-резервные-копии).

| Аудит SQL-миграций PostgreSQL | 30 000 ₽ / разовый заказ | Объём, материалы и срок согласуются письменно до оплаты; результат — электронный отчёт и рекомендации |

Продление Pro выполняется отдельным платежом, без автоматических списаний. Покупка аудита создаёт заказ на услугу и не включает Pro автоматически.

**Онлайн-оплата через Robokassa находится на этапе подключения.** Код интеграции готов для тестирования, но наличие кода не означает, что магазин активирован или реальные платежи уже работают. До оплаты согласуйте заказ через [контакты проекта](https://mars444456.github.io/lockguard/contacts.html).

Для запуска оплаты нужен отдельный доступный по HTTPS сервер с настроенными секретами Robokassa, ResultURL и сервисом чеков для самозанятого. Пароли задаются только в окружении сервера. Тестовый платёж не выдаёт рабочий доступ; переход на SuccessURL также не подтверждает оплату.

Возвраты оформляются через поддержку и кабинет провайдера; автоматическая синхронизация возвратов и отзыв доступа пока не реализованы. Генератор B2B-счёта выдаёт только образец без банковских реквизитов, который нельзя использовать для перевода денег.

Подробности: [развёртывание и интеграции](DEPLOYMENT.md), [оферта и возвраты](https://mars444456.github.io/lockguard/offer.html).

## Разработка

Сценарии корректности и порядок добавления регрессий: [TESTING.md](TESTING.md).

```sh
npm test
npm run build:browser
npm run build:legal
```

Отдельный прогон реальных блокировок требует локального одноразового PostgreSQL и переменной `LOCKGUARD_TEST_DATABASE_URL`, указывающей на БД с именем, заканчивающимся на `_test`:

```sh
npm run test:postgres
```

Обычный `npm test` не подключается к внешней базе. Матрица GitHub Actions настроена на PostgreSQL 14–18: ожидание DDL, создание индексов, FK и перепись таблицы при смене типа. Успех конкретного запуска проверяйте в CI. Тесты используют отдельную случайную схему в одноразовой тестовой БД.

- `src/core/` — парсер, правила, отчёты и генерация черновиков.
- `src/cli/`, `bin/` — CLI, Git hook и Telegram-бот.
- `src/server/`, `src/ui/` — сервер и локальный dashboard.
- `docs/` — статический сайт GitHub Pages и собранный браузерный анализатор.
- `config/seller.json` — публичные реквизиты для генерации юридических страниц.
- `test/` — тесты правил, CLI, HTTP, хранения, интеграций и SQL через PGlite.

После изменения ядра выполните `npm run build:browser` и включите в коммит `docs/lockguard-engine.js` вместе с `docs/libpg-query.wasm`. После изменения реквизитов выполните `npm run build:legal`.
