# LockGuard: Product & Technical Overview

## 1. Суть и ценность
* **One-liner:** Автоматический CI/CD-гейткипер и AST-анализатор миграций для PostgreSQL, который детектирует опасные блокировки таблиц (`ACCESS EXCLUSIVE`) и блокирует релизы до падения продакшена.
* **Целевая аудитория:** Бэкенд-разработчики, техлиды и DevOps в растущих B2B SaaS и e-commerce проектах (стеки Node.js/Prisma/Drizzle, Python/Alembic, Go), где размер таблиц превышает 500k–1M+ строк, и любая некорректная миграция замораживает транзакции и вызывает 504 Gateway Timeout.
* **Модель монетизации:** 
  * **Developer Free:** CLI-утилита для локального линтинга SQL/миграций (до 3 локальных проверок/день, открытый базовый набор правил).
  * **Team ($39/мес):** GitHub App / GitLab CI бот, безлимитные PR-проверки, автокомментарии в Pull Request с матрицей блокировок, безопасные SQL-альтернативы, Slack-алерты.
  * **Business ($99/мес):** Подключение к staging/read-only реплике БД для анализа реального объема данных (`pg_class.reltuples`, bloat-фактор) и динамического расчета времени лока.

## 2. Сценарий работы (Core User Flow)
* **Step 1 (Подключение):** Пользователь устанавливает GitHub Action в репозиторий проекта (1 `.github/workflows/lockguard.yml` файл) и привязывает API-ключ из личного кабинета LockGuard.
* **Step 2 (Триггер в PR):** Разработчик открывает Pull Request с новой миграцией (Prisma schema, Drizzle migration, Alembic `.py` или сырой `.sql`).
* **Step 3 (Парсинг и валидация):** 
  * CI-раннер LockGuard извлекает сгенерированный SQL-дифф.
  * SQL транслируется в абстрактное синтаксическое дерево (AST) через WebAssembly-парсер PostgreSQL (`libpg_query`).
  * Правила сопоставляются с матрицей уровней блокировок Postgres (например, выявление `ALTER TABLE ADD COLUMN ... DEFAULT <non-constant>`, `CREATE INDEX` без `CONCURRENTLY`, `ADD CONSTRAINT FOREIGN KEY` без `NOT VALID`).
* **Step 4 (Вердикт и фидбек):**
  * Если найдены критические антипаттерны: GitHub Action завершается с ошибкой (`status: failure`) и блокирует кнопку «Merge».
  * Бот оставляет в PR структурированный комментарий: уровень блокировки, затронутые таблицы, риск простоя и готовый безопасный многоэтапный SQL-сниппет для замены.
* **Step 5 (Одобрение или фикс):** Разработчик копирует предложенный безопасный паттерн, пушит коммит, чек становится зеленым, PR вливается без риска для прода.

## 3. Технический стек и зависимости
* **Frontend / UI (Минимум):**
  * **Фреймворк:** Next.js (App Router) + Tailwind CSS + shadcn/ui.
  * **Функционал:** Аутентификация через GitHub OAuth, генерация API-токенов команд, просмотр логов проверок и статусов PR, управление подпиской (billing portal).
* **Backend & Logic:**
  * **Язык/Среда:** Node.js / TypeScript (или Go для сверхбыстрого CLI).
  * **SQL AST Parser:** `pgsql-parser` (WebAssembly-библиотека на базе нативного парсера Postgres) — гарантирует 100% совместимость синтаксиса с реальным движком PostgreSQL.
  * **База данных сервиса:** PostgreSQL (Supabase или Neon) для хранения пользователей, проектов, логов проверок и правил.
  * **CLI Engine / GitHub Action:** Легковесный npm-пакет `@lockguard/cli` (компилируемый через `esbuild` в единый standalone-бандл).
* **Внешние интеграции / API:**
  * **GitHub REST & Checks API:** Создание Check Run, публикация аннотаций прямо в строках диффа кода, публикация комментариев к PR.
  * **Платежный шлюз:** Stripe Checkout + Customer Portal (или Lemon Squeezy для быстрой обработки глобальных SaaS-платежей с налогами MoR).
  * **Нотификации:** Incoming Webhooks (Slack / Discord / Telegram).

## 4. Границы MVP (Сборка за 48–72 часа)
* **Must Have:**
  * CLI-ядро на TypeScript с поддержкой анализа сырых `.sql` файлов.
  * Базовый движок правил (Top-8 фатальных антипаттернов):
    1. `ADD COLUMN` с выражением `DEFAULT` (для версий PG < 11 или с volatile-функциями).
    2. `CREATE INDEX` без модификатора `CONCURRENTLY` (блокирует `SHARE UPDATE EXCLUSIVE` -> запись блокируется).
    3. `ADD CONSTRAINT FOREIGN KEY` без `NOT VALID` (сканирует всю таблицу под строгим локом).
    4. `ALTER COLUMN TYPE` с конверсией, вызывающей полный rewrite таблицы.
    5. `ADD CONSTRAINT UNIQUE` напрямую (вместо связки `CREATE UNIQUE INDEX CONCURRENTLY` + `ADD CONSTRAINT USING INDEX`).
    6. `DROP TABLE` / `DROP COLUMN` в монолитном шаге без предварительного игнорирования на уровне ORM.
    7. Изменение `VACUUM` параметров во время транзакции миграции.
    8. Отсутствие `SET lock_timeout` в начале файла миграции (риск каскадного накопления очереди транзакций).
  * GitHub Action (композитный экшен), публикующий Markdown-таблицу с рисками в PR.
  * Минимальный Auth (GitHub Login) + выдача лицензионного ключа команды в UI.
* **Out of Scope (Откладываем на этап v1.1+):**
  * Прямое подключение к live-базе данных клиента для замера миллисекунд и проверки объема строк.
  * Поддержка MySQL, MariaDB, CockroachDB (фокус строго на PostgreSQL).
  * Нативные плагины для IDE (VSCode / JetBrains).
  * Автоматический авто-коммит исправлений (auto-PR).

## 5. Первые шаги для старта разработки
1. **Инициализация репозитория и парсера правил:**
   * Создать монорепозиторий (Turborepo / pnpm workspaces): `packages/core` (правила и парсер) и `packages/cli` (CLI-утилита).
   * Подключить `pgsql-parser`, написать юнит-тесты на 8 опасных паттернов DDL с фикстурами SQL.
2. **Разработка GitHub Action & Генератора отчетов:**
   * Реализовать CLI-команду `lockguard check ./migrations --format=github-pr-comment`.
   * Настроить Action-обертку, протестировать на тестовом репозитории с намеренно «опасным» PR (например, блокирующий `CREATE INDEX`).
3. **Облачный Gateway и авторизация:**
   * Поднять Next.js приложение: авторизация через GitHub, простая страница настроек проекта.
   * Настроить верификацию API-токена в CLI перед выполнением проверки в CI.
   * Подключить платежную ссылку Stripe Checkout с webhook-обработчиком активации тарифа `Team`.
