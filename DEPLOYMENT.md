# Развёртывание LockGuard

## Тестовый стенд

[Онлайн-кабинет для тестирования](https://lockguard-test-cabinet.onrender.com/#account) использует временное хранилище. Аккаунты, схемы и история могут сброситься при перезапуске; используйте учебные данные. После простоя первый запуск может занять около минуты.

`render.yaml` создаёт один веб-сервис на плане Free. Скрипт `scripts/cloud-demo-server.js` создаёт отдельную временную SQLite и не наследует рабочую базу, платёжные и административные секреты. Режим `--liftoff-only` ограничивает пиковую память компиляции WebAssembly. Автоматическое развёртывание отключено.

## Собственный сервер

Нужны Node.js 24+, HTTPS и постоянный диск для SQLite. Приложение отдаёт интерфейс и API с одного адреса.

1. Установите зависимости: `npm ci --omit=dev --ignore-scripts`.
2. Задайте настройки из `.env.example` в закрытом окружении сервера.
3. Укажите `NODE_ENV=production`, корневой `APP_URL=https://app.example.com`, постоянный `LOCKGUARD_DB_FILE` и каталог `LOCKGUARD_BACKUP_DIR`.
4. Запустите `npm start`; настройте прокси на порт приложения.
5. Проверьте регистрацию, вход, анализ, историю и сохранность данных после перезапуска. Проверьте восстановление резервной копии в отдельной тестовой базе.

`LOCKGUARD_ADMIN_TOKEN` предоставляет административный доступ и должен оставаться секретом. Клиентский адрес нельзя получать из произвольных заголовков прокси: при необходимости задайте только известные адреса в `LOCKGUARD_TRUST_PROXY_IPS`.

## Хранение и резервные копии

Командное ревью, резервные коды, шифрование и проверка восстановления описаны в [OPERATIONS.md](OPERATIONS.md). `npm run start:durable` предназначен для заранее подключённого постоянного тома; бесплатный тестовый Render остаётся временным.

SQLite содержит аккаунты, хеши паролей, сеансы, схемы, отчёты и сведения о заказах. Храните базу и копии в закрытых каталогах вне публичного сайта. Копия на том же диске не защищает от отказа диска; внешнее защищённое хранение настраивается оператором.

```sh
npm run backup
node scripts/restore-db.js /path/to/backup.sqlite3 /path/to/restored.sqlite3
```

Перед восстановлением остановите сервер и сохраните текущую базу. Скрипт восстановления не перезаписывает существующий файл. После восстановления активные сеансы отзываются. Сначала проверьте процедуру на учебных данных.

## Публичный сайт

`docs/` — статическая версия для GitHub Pages. Она анализирует SQL в браузере и не обрабатывает регистрацию.

В `config/site.json`:

- `applicationUrl` — корневой HTTPS-адрес постоянного кабинета.
- `demoUrl` — адрес временного тестового кабинета; переход сопровождается предупреждением.
- `donationUrl` — отдельная ссылка добровольной поддержки.

После изменения выполните `npm run build:browser`. Рабочие секреты, базы и внутренние материалы должны оставаться вне Git. `npm run check:privacy` проверяет рабочие файлы и подготовленный индекс перед публикацией.

## Интеграции

Переменные GitHub и Robokassa перечислены в `.env.example`. Задавайте реальные значения только на сервере. Для GitHub webhook нужен секрет подписи; выдавайте токену только необходимые разрешения выбранного репозитория.

Подключение реальной оплаты требует активированного магазина, согласованных адресов уведомлений и настройки чеков. Тестовые и рабочие пароли Robokassa разделяются. Доступ выдаётся по проверенному серверному уведомлению ResultURL; открытие SuccessURL не подтверждает оплату. Тестовый платёж не активирует оплаченный доступ.

Действующие условия услуг, цены и контакт для заказа находятся на [странице проекта](https://mars444456.github.io/lockguard/contacts.html).
