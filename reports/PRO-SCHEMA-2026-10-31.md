# LockGuard 1.2: схемы, Pro и реальные проверки блокировок

## Реализовано

- Открытый анализатор принимает снимок структуры SQL/JSON. В CLI добавлен `--schema`; схемы не исполняются. Хранятся только имена таблиц и столбцов, признаки NOT NULL, индексы и подтверждённые CHECK, без строк данных, исходных SQL и значений DEFAULT.
- Формат v1 ограничен 500 таблицами, 10000 столбцами, 2000 индексами и 512 КБ нормализованных данных. Неизвестные JSON-поля, DML, функции, динамический search_path и неподдерживаемые определения отклоняются.
- В Pro можно сохранить до 10 снимков своей организации, выбирать их в редакторе и передавать schemaId через API-ключ. Community сохраняет все 12 правил и открытый CLI; Pro добавляет серверный рабочий процесс.
- История Community ограничена 100 последними проверками, Pro — 1000. Сравнение двух полных новых проверок показывает новые, устранённые и оставшиеся замечания. Дубликаты сопоставляются по отдельности; смещение строк само по себе не создаёт новое замечание. При изменении снимка схемы показывается предупреждение.
- Доступ проверяется по организации и сроку на сервере. Клиентские plan/pro/organizationId не выдают права. Разовый аудит не считается лицензией Pro. После окончания срока схемы можно экспортировать и удалить; при новой записи старые отчёты сверх лимита Community удаляются.
- Для оператора есть локальная команда выдачи и отзыва доступа. Она не создаёт оплату и не делает самостоятельное повышение тарифа доступным клиенту.
- В интерфейсе появились вкладка схем, выбор контекста, сравнение и таблица различий тарифов. Выход очищает схемы и результаты; запоздалые ответы прежнего аккаунта игнорируются. Изменение SQL или выбранной схемы сбрасывает старый результат.

## Точность и ограничения

Индекс учитывается для FK только при подтверждённом подходящем префиксе btree. Частичные, невалидные, выраженные и нестандартные индексы не подавляют предупреждение. DROP INDEX, изменение search_path, удаление ограничений и изменение столбцов сбрасывают соответствующие доказательства. CREATE INDEX IF NOT EXISTS не доказывает наличие нужного индекса. Пример миграции исправлен: поддерживающий индекс строится до добавления FK.

Подтверждённый CHECK IS NOT NULL учитывается для PostgreSQL 12+, а NOT ENFORCED не считается подтверждением. При этом SET NOT NULL всё ещё требует ACCESS EXCLUSIVE: отсутствие замечаний не означает отсутствие блокировок. Уровень табличной блокировки теперь выводится по известным SQL-операциям независимо от количества замечаний; поле highestLockLevelBasis указывает на статический вывод, а не измерение.

Для добавления FK исправлен уровень SHARE ROW EXCLUSIVE на обеих таблицах: обычное чтение совместимо, запись может ждать. Оценки времени явно обозначены как модель, без обещания измеренной нижней границы. Средние замечания отображаются отдельно от результата без нарушений.

Снимок — утверждение пользователя о структуре. Он не доказывает актуальность рабочей базы, наличие строк или отсутствие иных зависимостей. Неподдерживаемые SQL-конструкции по-прежнему требуют ручной проверки. Для нескольких файлов CLI с --schema разрешён только независимый режим --isolated; автоматического проигрывания последовательности миграций нет.

## Проверка

Добавлены сценарии импорта, кавычек и схем имён, префиксов индексов, недостоверных доказательств, версий PostgreSQL, CLI, изоляции организаций, истечения Pro, серверных запретов, сохранения 1000 записей, сравнения, XSS и очистки интерфейса. Прогон реальных блокировок вынесен в npm run test:postgres и обязательный CI с PostgreSQL 14, 17 и 18. На этой Windows-машине PostgreSQL и Docker не установлены; локальный общий набор не подключается к внешним БД.

В настоящем браузере проверяются сохранение схемы, анализ, сравнение исправленной миграции, закрытый бесплатный режим и мобильное отображение. Тестовый Pro активирован только в отдельной QA-базе. Реальные платежи и пользовательские тарифы автоматически не изменялись.

Источники: [PostgreSQL — блокировки](https://www.postgresql.org/docs/current/explicit-locking.html), [ALTER TABLE — FK и валидация](https://www.postgresql.org/docs/current/sql-altertable.html), [node-postgres — запросы](https://node-postgres.com/features/queries).
