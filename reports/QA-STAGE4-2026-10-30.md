# LockGuard: Git, CI и документация — 30 октября 2026

## Исправления

- Проверки `check --staged` и `hook` читают содержимое индекса Git. Безопасный рабочий файл больше не скрывает опасный SQL, уже подготовленный к коммиту. Поддерживаются пробелы и кириллица в именах, переименования и удалённые рабочие копии.
- Ошибка Git завершает аудит кодом 2 вместо успешного пропуска. `--staged --fix` отклоняется: пользователь должен проверить изменения и самостоятельно добавить файл в индекс.
- Установка pre-commit hook сохраняет существующий hook, сообщая о необходимости ручного объединения проверок.
- Автоисправление CREATE INDEX использует AST и байтовые смещения токенов PostgreSQL. Оно сохраняет комментарии, строковые данные и тела процедур, включая SQL с Unicode. Результат разбирается повторно до записи; неподходящий таймаут не записывается.
- CI отличает найденный риск (код 1) от ошибки анализатора (код 2). Для PR отчёт строится по действительно изменённым SQL-миграциям относительно базового коммита, а не по учебному fixture. SQL в fixtures/ и test/ проверяется тестами. Отчёт сохраняется как артефакт без публикации комментариев в PR.
- Генератор workflow использует Action из этого репозитория вместо непроверенного npm-пакета и не перезаписывает существующий workflow.
- Образец B2B-счёта содержит ФИО, ИНН и контакты из config/seller.json, а цены — из общего каталога. Вымышленные ИП, счёт, телефон и указание УСН удалены. Без банковских реквизитов документ явно помечен «не для оплаты». Неизвестный тариф отклоняется.
- README переписан: актуальные запуск, API, ограничения, статус Robokassa, стоимость услуг, реквизиты и документы. Добавлен текст ранее заявленной лицензии MIT и команда build:legal. Убраны отдельные обещания 100% безопасности в интерфейсах.
- Проверка сайта после публикации выявила отсутствующие элементы счётчика нарушений: добавлены в HTML. Ошибки SQL показываются внутри страницы и очищают старые результаты. Разбиение и PDF дожидаются анализа текущего текста; SQL экранируется в HTML, включая сгенерированные фазы и печатный отчёт. Для неполного анализа исполняемые черновики не выдаются.
- Добавлены регрессионные тесты настоящего HTML и app.js в DOM через linkedom (зависимость только для разработки): отчёт по опасной миграции, смена входного SQL, ошибка разбора и HTML внутри SQL.
- Первый удалённый CI прошёл тесты и выявил только различие режима файла WASM: npm-пакет копировал его как исполняемый на Linux. Сборка теперь явно выставляет 0644 для статического файла.
- Сборка добавляет хеш содержимого к URL JavaScript в index.html, чтобы браузер и CDN не смешивали новый HTML со старым app.js после публикации. CI проверяет также актуальность этих ссылок.

## Что ещё требуется для эксплуатации

- Завершить активацию магазина Robokassa, настроить отдельный HTTPS backend и секреты в окружении, проверить настоящий платёж, ResultURL и чек. Реальные платежи этим аудитом не проводились.
- Для самостоятельной покупки разными клиентами необходимы аккаунты, изоляция организаций и серверный контроль платных функций. Текущий dashboard обслуживает одну организацию и требует администраторского токена для создания заказа.
- JSON-хранилище рассчитано на один процесс записи. Для нескольких экземпляров сервера нужна полноценная база данных и восстановление/резервное копирование.
- Сверка возвратов, автоматический отзыв доступа и фоновая очередь GitHub webhook пока не реализованы.
- Статический анализ и шаблоны split имеют ограниченное покрытие. Черновики необходимо сверять с исходной миграцией и проверять на тестовой базе до применения.
