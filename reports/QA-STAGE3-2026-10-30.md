# Третий этап: PostgreSQL AST и интеграции

**Актуализация оплаты:** по последующему выбору пользователя Stripe заменён на Robokassa для самозанятого. Текущие настройки — в [инструкции по российской оплате](RF-PAYMENTS-SETUP.md). Ниже сохранены результаты предыдущего этапа.

Реализованы runtime-подключение libpg-query, выполнение тестовых миграций в PGlite, обработка подписанных webhook GitHub и Stripe. Настройки и ограничения описаны в [инструкции](INTEGRATIONS-SETUP.md).

Итоговый прогон: **146/146 тестов**, без пропусков. Синтаксис обоих app.js и git diff --check также проверены.

## Изменения

- SQL проверяется штатной грамматикой PostgreSQL 18 до запуска правил. Адаптер берёт из AST имена таблиц и колонок, типы, выражения default, поля FK, параметры индекса и ограничения. Старый разбор оставлен для совместимости метаданных правил; неизвестные операции блокируются. Синтаксически недопустимый SQL возвращает ошибку CLI 2 / HTTP 422.
- Сохраняются quoted identifiers и Unicode; строка 'random()' не считается вызовом функции. Неизвестные функции в DEFAULT трактуются консервативно, функции внутри DML требуют ручного анализа.
- Составные, частичные и expression-индексы больше не дают ложного подтверждения поддержки FK. Проверка NOT NULL учитывает порядок VALIDATE и DROP CHECK.
- В генераторе и FK-рекомендациях сохранены реальные referenced columns и ON DELETE. У фаз UUID/NOT NULL добавлено фактическое SET NOT NULL и удаление вспомогательного CHECK. Генерируемые имена NOT NULL CHECK безопасны для кавычек и ограничения длины PostgreSQL.
- Устранён Windows/libuv crash в CLI: принудительный process.exit заменён на process.exitCode для штатного завершения WebAssembly.
- GitHub проверяет HMAC исходного тела, allowlist репозиториев, получает файлы по API и анализирует реальный SQL по blob SHA. До и после анализа проверяет head SHA. Публикация commit status включается отдельно; по умолчанию внешние записи отключены. Ответы API читаются с ограничением размера.
- Stripe использует официальный SDK, реальные Checkout и Customer Portal. Paid checkout проверяется через Session/Subscription API, организация и Price сверяются на сервере, повторные и устаревшие события не подменяют актуальное состояние подписки. HTTP webhook использует подпись, а не администраторский Bearer-токен.
- Кнопка выбора тарифа открывает Checkout, если он настроен. Новые организации начинают с free.
- Добавлены pinned зависимости и lockfile, CI/Action/Docker обновлены для npm ci. Браузерная сборка включает общий адаптер и WASM рядом с JS.

## Проверки

Полный тестовый набор и дополнительные интеграционные тесты выполнены локально. Отдельные PostgreSQL-тесты запускаются без пользовательской БД. Подписи проверены настоящим Stripe SDK и HMAC GitHub; API провайдеров заменены локальными ответами. Оба webhook дополнительно проверены через реальный локальный HTTP-сервер с Unicode в исходном теле и отрицательными сценариями подмены байтов.

## Границы результата

Полная PostgreSQL-грамматика не означает полной модели рисков каждой операции. Адаптер и 12 предметных правил всё ещё покрывают ограниченный набор операций. LG-000 требует ручного анализа неизвестных конструкций. AutoSplitter остаётся черновым генератором; произвольная миграция не доказана эквивалентной набору его фаз.

Для настоящего запуска интеграций нужны параметры GitHub/Stripe, публичный HTTPS endpoint и проверка доставки событий в test mode. У пользователя они пока не настроены. Для проверки конкурентных блокировок нужен отдельный многопроцессный PostgreSQL. Существующее JSON-хранилище и синхронная обработка GitHub webhook ограничивают масштабирование; это описано в инструкции.
