🛡️ Интерактивная матрица совместимости блокировок PostgreSQL

Почему падает продакшен при накатывании миграций? В PostgreSQL блокировки берутся не только на строки, но и на всю таблицу целиком. Выберите любой уровень блокировки или типовую операцию, чтобы увидеть конфликты в реальном времени и понять, почему ваш DDL может вызвать лавину 504 ошибок.

Запрашиваемый Lock (Строка) \ Существующий (Столбец) ACCESS SHARE ROW SHARE ROW EXCL SHARE UPD EXCL SHARE SHARE ROW EXCL EXCLUSIVE ACCESS EXCL
🚨 ACCESS EXCLUSIVE: Фатальная блокировка таблицы (Full Outage Risk)
Блокирует абсолютно все операции: чтение (SELECT), запись (INSERT, UPDATE, DELETE), создание индексов и любые другие DDL/DML. Если в этот момент выполняется долгий аналитический запрос, DDL встает в очередь, а все последующие SELECT выстраиваются за ним (Head-of-Line Blocking), исчерпывая пул соединений и приводя к массовым ошибкам HTTP 504 Gateway Timeout.
⛔ Блокирует: SELECT ⛔ Блокирует: INSERT / UPDATE / DELETE ⛔ Блокирует: CREATE INDEX ⛔ Блокирует: VACUUM
